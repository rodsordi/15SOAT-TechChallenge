# ADR 001: Adoção do PostgreSQL como Banco de Dados Principal Relacional

**Data:** 06 de Maio de 2024  
**Status:** Aceito  
**Responsáveis:** [Rodrigo de Sordi/Equipe de Arquitetura]

## 1. Contexto e Problema

Estamos desenvolvendo um novo sistema de backend (API) que será responsável por gerenciar clientes, veículos, ordens de serviços, estoque. Para suportar essa aplicação, precisamos escolher um sistema de gerenciamento de banco de dados (SGBD) para armazenamento persistente.

Os principais requisitos técnicos e de negócio levantados são:
* **Consistência de Dados:** O sistema lidará com dados transacionais críticos onde a integridade referencial e a garantia de propriedades ACID são inegociáveis.
* **Consultas Complexas:** A API precisará realizar agregações, junções (JOINs) e relatórios em tempo real envolvendo múltiplas entidades.
* **Flexibilidade Mista:** Embora os dados sejam predominantemente estruturados, existem fluxos que se beneficiariam de uma estrutura flexível semelhante a documentos (JSON).
* **Ecossistema:** Necessidade de uma tecnologia madura, open-source e com ampla adoção na comunidade.

## 2. Decisão

Decidimos utilizar o **PostgreSQL** como o banco de dados relacional primário. Para a infraestrutura, adotaremos uma abordagem de banco de dados gerenciado em nuvem AWS RDS para reduzir a sobrecarga operacional de manutenção e backups.

## 3. Justificativa

O PostgreSQL foi escolhido pelas seguintes razões:

* **Conformidade ACID:** Oferece suporte robusto a transações, garantindo que os dados permaneçam consistentes mesmo em caso de falhas de hardware ou erros de energia.
* **Ecossistema e Ferramentas:** Compatibilidade total com os principais ORMs (Hibernate) e ferramentas de migração, além de uma vasta comunidade para suporte.
* **Custo-Benefício:** Sendo open-source, não há custos
